# Устранение неполадок

Сообщения об ошибках сбора показываются у каждого хоста в отчёте. Подробный вывод сбора хранится в `/data/jobs/<id>/`, журнал сервиса — в stdout контейнера (`docker logs amberventory`, `kubectl -n amberventory logs deploy/amberventory`).

## Сбор

| Сообщение | Причина | Что сделать |
|---|---|---|
| «SSH: доступ запрещён» | ключ не добавлен в `authorized_keys`, указан не тот пользователь или вход этим пользователем запрещён в `sshd` | проверьте вручную: `ssh -i <ключ> <пользователь>@<хост>`; проверьте `ansible_user` в inventory и поле пользователя при запуске |
| «SSH: таймаут подключения» | хост недоступен из сети сервиса, порт закрыт межсетевым экраном, медленный ответ `sshd` (например, из-за обратного DNS) | проверьте маршрут и правила МЭ из окружения сервиса ([сеть](deployment.md#сеть-и-сканирование)); увеличьте `AMBER_SSH_TIMEOUT` |
| «SSH: соединение отклонено» | `sshd` не слушает указанный порт | проверьте порт (`ansible_port` в inventory) |
| «Хост недоступен по сети» | нет маршрута до хоста | проверьте сетевой режим сервиса и NetworkPolicy |
| «SSH: проблема с host key» | включена проверка ключей, а ключа хоста нет в `known_hosts` или он изменился | добавьте актуальный ключ ([security.md](security.md#проверка-ключей-хостов)); изменившийся ключ сначала проверьте: это может быть подмена хоста |
| «sudo/become не удался» | включена опция «Запускать сборщик целиком через sudo», а у пользователя нет sudo без пароля на любые команды | выключите опцию и используйте ограниченный sudo ([requirements.md](requirements.md#ограниченный-sudo)) |
| «Ключ защищён паролем: введите passphrase» | ключ зашифрован, passphrase не введена или сервис перезапускался | введите passphrase в форме ключа |
| Сбор прерывается на большом парке | превышен `AMBER_JOB_TIMEOUT` | увеличьте лимит или разбейте inventory на группы |
| Часть разделов отчёта пустая (процессы портов, сертификаты, параметры `sshd`) | сбор шёл без повышенных прав | настройте ограниченный sudo ([requirements.md](requirements.md#что-требует-повышенных-прав)) |

## Сканирование и inventory

| Сообщение | Причина | Что сделать |
|---|---|---|
| «Слишком большой диапазон» | число адресов превышает `AMBER_MAX_SCAN_HOSTS` | сканируйте подсеть частями или увеличьте лимит |
| Хосты не находятся, хотя доступны с вашего компьютера | сервис работает в другом сетевом окружении (bridge-сеть Docker, сеть подов) | см. [Сеть и сканирование](deployment.md#сеть-и-сканирование) |
| «Inventory не разобран» | синтаксическая ошибка в файле | проверьте файл командой `ansible-inventory -i <файл> --list` |

## Базы уязвимостей

| Симптом | Причина | Что сделать |
|---|---|---|
| Базы не обновляются, в журнале ошибки загрузки | нет доступа к источникам | проверьте доступ к адресам из [requirements.md](requirements.md#сеть), настройте `HTTPS_PROXY` или зеркала |
| Отчёт предупреждает, что списки пакетов apt устарели | на хосте давно не выполнялся `apt-get update`; доступные обновления определены по старому кэшу | включите «Обновить списки пакетов» при сборе или обновляйте кэш на хостах штатно |
| «apt не видит обновление» у находки | исправленная версия есть в Debian, но не видна apt на хосте | проверьте, подключён ли на хосте репозиторий `security.debian.org`, и актуальность списков пакетов |
| Загрузка CVSS из NVD идёт медленно | без ключа API NVD ограничивает частоту запросов (около 6 с на CVE) | задайте `NVD_API_KEY` |
| Ручная загрузка JSON трекера обрывается | reverse proxy ограничивает размер запроса | увеличьте лимит до 128 МБ ([deployment.md](deployment.md#reverse-proxy)) |

## Сервис

| Симптом | Причина | Что сделать |
|---|---|---|
| Под перезапускается с `OOMKilled` | не хватает памяти при большом `AMBER_FORKS` | уменьшите `config.forks` или увеличьте лимит памяти |
| После перезапуска сбор требует passphrase | passphrase хранится только в памяти | ожидаемое поведение, введите её снова |
| `docker pull` возвращает `not found` | тег не существует (например, `latest` до первого релиза) или пакет приватный | проверьте тег ([deployment.md](deployment.md#образ)), выполните `docker login ghcr.io` |
