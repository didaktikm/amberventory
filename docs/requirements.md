# Требования

## Совместимость

| Компонент | Поддержка | Как проверено |
|---|---|---|
| Хосты Debian 8–13 | инвентаризация и оценка уязвимостей | разбор вывода сборщика покрыт тестами на образцах; на реальных хостах каждого релиза не проверялось |
| Другие дистрибутивы (Ubuntu и т. п.) | только инвентаризация | не проверялось |
| Образ сервиса | `linux/amd64`, `linux/arm64` | обе архитектуры собираются в CI; e2e-тест выполняется на `amd64` |
| Docker | Docker Engine; для Compose — плагин Compose v2 | не проверялось в CI |
| Kubernetes | 1.25+ (`kubeVersion` чарта) | манифесты проверяются по схемам Kubernetes 1.31; e2e-установка в kind |
| Helm | 3.8+ (поддержка OCI) или 4.x | чарт разрабатывается и проверяется на Helm 4 |

Поддерживаемые релизы Debian и сроки их поддержки заданы в таблице `DEBIAN_RELEASES` в `app/config.py` и сверяются с [Debian LTS](https://wiki.debian.org/LTS). Хост на релизе с истёкшей поддержкой отмечается в отчёте как EOL.

Результаты проверки на реальных хостах вносите в эту таблицу по итогам пилотной эксплуатации.

## Сайзинг

Нагрузочных замеров пока нет. Ниже приведены факторы, которые определяют потребление ресурсов, и стартовые значения. Уточните их по итогам пилота.

| Ресурс | От чего зависит | Стартовое значение |
|---|---|---|
| CPU | число параллельных SSH-сессий (`AMBER_FORKS`): каждая — отдельный процесс Ansible; разбор и анализ отчёта | запрос 100m, без лимита (значения чарта по умолчанию) |
| Память | `AMBER_FORKS`; импорт трекера Debian выполняется потоково и не загружает файл целиком | запрос 512 MiB, лимит 2 GiB |
| Диск | базы уязвимостей (JSON трекера Debian около 60 МБ и SQLite-база, построенная из него); отчёты (растут с числом хостов и пакетов) | том 5 GiB |
| Длительность сбора | число хостов, `AMBER_FORKS`, `AMBER_SSH_TIMEOUT` и доля недоступных хостов | лимит одного сбора 1800 с (`AMBER_JOB_TIMEOUT`) |

Для больших парков разбивайте inventory на группы и увеличивайте `AMBER_JOB_TIMEOUT`, если сбор не укладывается в лимит. Рост `AMBER_FORKS` ускоряет сбор, но линейно увеличивает число процессов и потребление памяти.

## Сеть

| Направление | Назначение | Порт | Зачем |
|---|---|---|---|
| Входящее | веб-интерфейс сервиса | 443 на reverse proxy или Ingress (сервис слушает 8080) | доступ администраторов |
| Исходящее | хосты | TCP 22 или порт из inventory (`ansible_port`) | сбор по SSH |
| Исходящее | адреса сканируемой подсети | TCP-порт SSH, указанный при сканировании | поиск хостов (nmap) |
| Исходящее | `security-tracker.debian.org` | 443 | Debian Security Tracker |
| Исходящее | `www.cisa.gov` | 443 | CISA KEV |
| Исходящее | `epss.empiricalsecurity.com`, резервный `epss.cyentia.com` | 443 | FIRST EPSS |
| Исходящее | `services.nvd.nist.gov` | 443 | CVSS из NVD, только по запросу из отчёта |
| Исходящее | `ghcr.io` | 443 | загрузка образа и чарта при установке и обновлении |
| Исходящее | DNS | 53 | разрешение имён хостов и источников |

Выход в интернет через прокси настраивается переменными `HTTPS_PROXY` и `NO_PROXY`. Без доступа в интернет используйте внутренние зеркала: [deployment.md](deployment.md#изолированный-контур).

## Доступ к хостам

На каждом хосте нужны:

- учётная запись для сборщика (рекомендуется отдельная, например `amberventory`) с командной оболочкой bash;
- открытый ключ сервиса в `~/.ssh/authorized_keys` этой учётной записи;
- запись в домашний каталог: Ansible временно копирует туда скрипт сборщика (`~/.ansible/tmp`) и удаляет его после выполнения.

### Что требует повышенных прав

Без root и без `sudo` сборщик работает, но часть данных будет неполной. Отчёт пока не показывает явно, что сбор шёл без повышенных прав: пустые разделы в таблице ниже — признак этого.

| Данные | Команда | Без прав |
|---|---|---|
| Процессы, слушающие порты | `ss -lntup` (`netstat` на старых системах) | порты видны, процессы — нет |
| Число ключей в `authorized_keys` других пользователей | `test`, `grep` | не собирается |
| Состояние паролей учётных записей | `getent shadow` | не собирается |
| TLS-сертификаты в закрытых каталогах (`/etc/letsencrypt` и др.) | `openssl x509` | только сертификаты, доступные на чтение |
| Эффективные параметры `sshd` | `sshd -T` | не собирается |
| Запущенные контейнеры | `docker ps` | только если пользователь в группе `docker` |
| Обновление списков пакетов (опция «Обновить списки пакетов») | `apt-get update` | опция не выполняется |

Повышенные права можно получить двумя способами:

| Способ | Как работает | Что нужно на хосте |
|---|---|---|
| Ограниченный sudo (рекомендуется) | опция «Запускать сборщик целиком через sudo» выключена; сборщик проверяет `sudo -n true` и вызывает через `sudo -n` только команды из таблицы выше | правило из раздела [Ограниченный sudo](#ограниченный-sudo) |
| Сборщик целиком от root | опция включена; Ansible запускает весь скрипт через `sudo` (`--become`) | `sudo` без пароля на любые команды, то есть полный root |
| Вход под root | SSH-пользователь `root` | разрешённый вход root по ключу |

Если `sudo` без пароля недоступен и опция выключена, сбор выполняется без повышения прав.

### Ограниченный sudo

Список составлен по коду `ansible/collector.sh` и должен сверяться с ним при каждом изменении сборщика. Пути указаны для систем с объединённым `/usr` (Debian 12+) и без него (Debian 11 и старше):

```sudoers
# /etc/sudoers.d/amberventory — права сборщика AmberVentory
Cmnd_Alias AMBER_READ = /usr/bin/true, /bin/true, \
                        /usr/bin/test, \
                        /usr/bin/grep, /bin/grep, \
                        /usr/bin/getent shadow *, \
                        /usr/bin/ss, /bin/ss, /bin/netstat, \
                        /usr/bin/openssl x509 *, \
                        /usr/sbin/sshd -T
Cmnd_Alias AMBER_OPTIONAL = /usr/bin/docker ps *, \
                            /usr/bin/apt-get update -qq

amberventory ALL=(root) NOPASSWD: AMBER_READ
# Раскомментируйте, если нужны список контейнеров и обновление списков пакетов:
# amberventory ALL=(root) NOPASSWD: AMBER_OPTIONAL
```

Проверка: `visudo -cf /etc/sudoers.d/amberventory` и `sudo -l -U amberventory`.

Важно для согласования со службой безопасности: `grep` и `test` с правами root позволяют читать любой файл на хосте. Правило не даёт права на изменение системы, но даёт полный доступ на чтение, в том числе к `/etc/shadow`. Если это неприемлемо, исключите `grep` и `test` из правила: сервис перестанет считать ключи в `authorized_keys` других пользователей, остальные данные соберутся.

Этот sudoers-файл не проверялся на реальных хостах. Перед раскаткой проверьте его на тестовом хосте каждого используемого релиза.
