# Безопасность

## Модель угроз

Сервис хранит приватный SSH-ключ с доступом ко всем хостам парка и формирует отчёты, которые описывают уязвимости этих хостов. Компрометация сервиса означает доступ к парку и готовую карту атаки. Поэтому сервис эксплуатируется как бастион:

- доступ к интерфейсу только из административного сегмента, через TLS;
- аутентификация включена всегда;
- на хостах — отдельная учётная запись с минимальными правами ([requirements.md](requirements.md#доступ-к-хостам));
- сервис не публикуется в интернет.

## Аутентификация

Сервис поддерживает одну учётную запись HTTP basic auth (`AMBER_USER`, `AMBER_PASSWORD`). Пароль сравнивается за постоянное время. `/healthz` доступен без аутентификации для проверок живости.

Ограничения:

- одна общая учётная запись на всех пользователей;
- нет SSO, ролей и разграничения доступа к отчётам;
- нет журнала действий пользователей.

Если нужна персональная аутентификация, поставьте перед сервисом прокси с SSO, например [oauth2-proxy](https://oauth2-proxy.github.io/oauth2-proxy/) с корпоративным провайдером OIDC, и ограничьте прямой доступ к сервису сетью. Журнал прокси даёт сведения о том, кто и когда обращался к сервису. Basic auth в самом сервисе при этом оставьте включённой как второй рубеж.

## Секреты

| Секрет | Где хранится | Рекомендации |
|---|---|---|
| Пароль интерфейса | переменная окружения процесса | Docker: файл `--env-file` с правами `600`, не аргументы командной строки; Kubernetes: Secret через `auth.existingSecret`, не `--set auth.password` (значение попадает в историю релиза Helm) |
| SSH-ключ | `/data/keys` на томе, права `600` | храните исходный ключ в хранилище секретов; ограничьте доступ к тому и резервным копиям |
| Passphrase ключа | только память процесса | вводится после каждого перезапуска |
| Расшифрованная копия ключа | `/data/jobs/<id>/id_key` на время сбора, удаляется по его завершении | при аварийной остановке во время сбора копия может остаться на томе: проверяйте `jobs/` после сбоев |
| Ключ API NVD | переменная окружения | Kubernetes: `nvd.existingSecret` |

Переменные окружения видны в `docker inspect` и в описании пода тем, у кого есть доступ к Docker или к Kubernetes API. Ограничьте этот доступ.

## Сеть

- Сервис слушает HTTP без TLS. TLS завершается на reverse proxy или Ingress ([deployment.md](deployment.md#reverse-proxy)).
- Сервис доверяет заголовкам `X-Forwarded-*` от любого источника. Не публикуйте порт сервиса напрямую, только через прокси.
- В Kubernetes включите `networkPolicy.enabled` и ограничьте входящий трафик контроллером Ingress ([deployment.md](deployment.md#сеть-и-сканирование)).
- Ответы содержат заголовки `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`.

## Проверка ключей хостов

По умолчанию ключи хостов не проверяются: иначе первый сбор по новой подсети завершится ошибкой для всех хостов. Это допускает подмену хоста при атаке «человек посередине».

Для рабочей эксплуатации включите проверку:

1. Соберите ключи хостов доверенным способом, например `ssh-keyscan` из защищённого сегмента или из системы управления конфигурацией.
2. Передайте их сервису: Docker — смонтируйте файл в `/home/amber/.ssh/known_hosts` (только чтение); Kubernetes — параметр `knownHosts`.
3. Включите «Проверять host key» при запуске сбора.

## Контейнер

Образ запускается от непривилегированного пользователя (UID 10001), PID 1 — `tini`. Helm-чарт дополнительно включает read-only корневую файловую систему, сбрасывает все capabilities, включает профиль seccomp `RuntimeDefault` и не монтирует токен ServiceAccount. В Docker эти ограничения не применяются автоматически.

## Воздействие на хосты

Сборщик не изменяет конфигурацию и пакеты. На время сбора Ansible копирует скрипт сборщика во временный каталог в домашнем каталоге пользователя и удаляет его после выполнения. С опцией «Обновить списки пакетов» выполняется `apt-get update`, который обновляет кэш apt.
